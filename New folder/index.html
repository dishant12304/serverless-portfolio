What I actually do

Most of my work sits at the seam between infrastructure and application code — deciding what runs where, and making sure it deploys the same way every time.

Design for cost, not just for scale

Pay-per-request beats an idle EC2 box for most portfolio-sized and early-stage workloads. I default to managed and serverless unless there's a real reason not to.

Automate the boring parts

If I deploy something by hand twice, the third time is a GitHub Actions workflow. Infrastructure changes should be reviewable, not remembered.

Keep the blast radius small

Least-privilege IAM roles, scoped permission sets, no long-lived access keys. Root stays locked in a drawer.
